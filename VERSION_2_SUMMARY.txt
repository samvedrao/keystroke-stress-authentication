🔄 HOW THE SYSTEM WORKS
═══════════════════════════════════════════════════════════════════════════════

USER REGISTRATION:
  1. Visit /register
  2. Enter: username, email, password
  3. Form validation (client + server)
  4. Password hashed with SHA256
  5. User stored in database
  6. Redirected to login

USER LOGIN:
  1. Visit /login
  2. Enter: username, password
  3. Password verified against stored hash
  4. Session created (7-day expiration)
  5. Redirected to /dashboard

TYPING ANALYSIS:
  1. User types in textarea
  2. JavaScript captures every keydown/keyup
  3. Calculates hold times (key pressed duration)
  4. Calculates flight times (gap between keys)
  5. Updates live statistics on screen
  6. User clicks "Analyze"
  7. Features sent to /api/predict/stress
  8. Flask loads 2 trained models
  9. Random Forest predicts → {prediction, confidence}
  10. XGBoost predicts → {prediction, confidence}
  11. Ensemble combines predictions
  12. Session saved to database
  13. Results displayed with interpretation
  14. User can see all history in dashboard

DATA STORAGE:
  • Users table: id, username, email, password_hash, created_at
  • Sessions table: id, user_id, 8 features, 3 predictions, metadata
  • Each user has 1:N relationship to sessions
  • All data persisted in keystroke_db.db

📊 IMPROVED MODEL CONSISTENCY
═══════════════════════════════════════════════════════════════════════════════

WHY DIFFERENT PREDICTIONS?
━━━━━━━━━━━━━━━━━━━━━━━━━
Different models learn different patterns
RF might prioritize certain features more than XGB
Their decision boundaries naturally differ

SOLUTION IMPLEMENTED:
━━━━━━━━━━━━━━━━━━━
1. Random Forest improvements:
   • n_estimators=200 (vs 100) - more trees = more robust
   • max_depth=15 (vs default ~None) - lets it learn details
   • min_samples_split=5 (vs 2) - less prone to overfitting
   • class_weight='balanced' - fair on both classes

2. XGBoost improvements:
   • n_estimators=200 (vs 100) - more gradual learning
   • learning_rate=0.05 (vs 0.1) - slower = more stable
   • max_depth=7 (vs 6) - balanced complexity
   • subsample=0.8 - use 80% of data per tree
   • colsample_bytree=0.8 - use 80% of features per tree

3. Ensemble prediction (NEW!):
   • Both models often agree
   • When they disagree, confidence weighted voting
   • Formula: (RF_pred * RF_conf + XGB_pred * XGB_conf) / (RF_conf + XGB_conf)
   • Result: More reliable consensus
