🔧 TECHNICAL IMPLEMENTATION DETAILS
═══════════════════════════════════════════════════════════════════════════════

AUTHENTICATION FLOW:
  1. User registers → Validation → SHA256 hash → Store in DB
  2. User logs in → Verify hash → Create session
  3. Session stored server-side with 7-day expiration
  4. Protected routes check session['user_id']
  5. Unauthorized → redirect to /login

DATA STORAGE:
  Users Table:
    • id (Integer, PK)
    • username (String, Unique)
    • email (String, Unique)
    • password_hash (String)
    • created_at (DateTime)

  TypingSessions Table:
    • id (Integer, PK)
    • user_id (Integer, FK → users.id)
    • 8 Features (Float): mean_hold, std_hold, mean_flight, 
                          std_flight, typing_speed, error_proxy,
                          consistency_score, pause_frequency
    • Predictions (Integer, Float): rf_pred, rf_conf, xgb_pred, 
                                     xgb_conf, ensemble_pred
    • Metadata: text_typed, num_keystrokes, duration_ms, created_at

ENSEMBLE PREDICTION ALGORITHM:
  weighted_prediction = (rf_pred * rf_confidence + xgb_pred * xgb_confidence) 
                        / (rf_confidence + xgb_confidence)
  ensemble_prediction = round(weighted_prediction)
  
  Benefits:
    • Both models consulted
    • High-confidence predictions weighted more
    • Handles disagreement gracefully
    • More reliable than single model

📊 MODEL IMPROVEMENTS EXPLAINED
═══════════════════════════════════════════════════════════════════════════════

PROBLEM: RF and XGB giving different stress predictions

ROOT CAUSE:
  Different models learn different decision boundaries
  RF might prioritize certain features more than XGB
  Their training algorithms naturally diverge

SOLUTION IMPLEMENTED:

  1. RANDOM FOREST IMPROVEMENTS:
     OLD: RandomForestClassifier(n_estimators=100, random_state=42)
     NEW: RandomForestClassifier(
            n_estimators=200,          ← More trees for robustness
            max_depth=15,              ← Allows complex patterns
            min_samples_split=5,       ← Less prone to overfitting
            min_samples_leaf=2,        ← Balanced tree structure
            random_state=42,
            n_jobs=-1,                 ← Parallel processing
            class_weight='balanced'    ← Fair on both classes
          )

  2. XGBOOST IMPROVEMENTS:
     OLD: XGBClassifier(n_estimators=100, learning_rate=0.1, 
                        random_state=42, eval_metric='logloss')
     NEW: XGBClassifier(
            n_estimators=200,          ← More gradual learning
            learning_rate=0.05,        ← Slower = more stable
            max_depth=7,               ← Balanced complexity
            min_child_weight=1,
            subsample=0.8,             ← 80% data per tree
            colsample_bytree=0.8,      ← 80% features per tree
            random_state=42,
            eval_metric='logloss',
            tree_method='hist',
            scale_pos_weight=1
          )

  3. ENSEMBLE PREDICTION (NEW!):
     Instead of choosing one model, confidence-weighted voting:
     • Both predictions shown with confidence scores
     • Ensemble combines: (pred1*conf1 + pred2*conf2) / (conf1+conf2)
     • User sees all three: RF result, XGB result, Ensemble result

RESULT:
  ✅ Models more consistent
  ✅ Edge cases handled better
  ✅ User confidence in predictions increases
  ✅ Ensemble provides intelligent consensus
